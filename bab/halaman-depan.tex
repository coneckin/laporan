\chapter*{ABSTRAK}
\addcontentsline{toc}{chapter}{ABSTRAK}

Jaringan WiFi kampus umumnya menggunakan mekanisme \textit{captive portal} berbasis web yang mengharuskan pengguna memasukkan kredensial secara berulang setiap kali sesi terputus atau perangkat berpindah titik akses. Proyek 2 ini mengembangkan, melengkapi, dan memverifikasi ekosistem aplikasi \textbf{Coneckin} yang terdiri atas aplikasi Android native berbasis Kotlin dan Jetpack Compose, layanan API REST berbasis Node.js (Express 5) dan MongoDB (\texttt{coneckin\_db}), serta halaman panduan dan unduhan berbasis konvensi modular Croot.js pada GitHub Pages (\texttt{coneckin.github.io}).

Penyempurnaan utama mencakup pemenuhan arsitektur \textit{Hybrid CRUD} secara utuh melalui penambahan fitur \textit{Ubah Akun}, validasi duplikasi akun, ekspor/impor cadangan, serta penguatan keamanan akses lokal (\textit{PIN} berbasis PBKDF2WithHmacSHA256 dengan jeda penguncian otomatis, fitur pemulihan \textit{Lupa PIN}, verifikasi per sesi, \texttt{BIOMETRIC\_STRONG}, dan minifikasi R8) di atas penyimpanan terenkripsi AES-256 GCM (\texttt{AndroidKeyStore}). Pada sisi server, diimplementasikan operasi \textit{Create}, \textit{Read}, \textit{Update}, dan \textit{Delete} pada endpoint (\texttt{/portals}, \texttt{/config}, \texttt{/reports}) yang dilindungi autentikasi token admin berbasis perbandingan aman waktu-konstan (SHA-256 \texttt{timingSafeEqual}) dan middleware CORS untuk endpoint baca publik. Dari sisi penjaminan mutu, diterapkan pengujian otomatis berlapis dengan hasil 90 \textit{unit test} JVM Android dengan \textit{line coverage} 97,02\%, 11 \textit{instrumented test} perangkat Android untuk validasi \texttt{AndroidKeyStore}, serta 39 tes otomatis pada server Express dengan \textit{line coverage} 96,53\% (total 140 skenario otomatis). Seluruh pengujian terintegrasi dalam alur CI/CD GitHub Actions yang mensyaratkan ambang \textit{coverage} minimal 80\% sebelum merilis APK ringkas ($\approx 2{,}25$~MB) dan AAB, serta telah tervalidasi berjalan sinkron di lingkungan produksi Alwaysdata dan GitHub Pages.

\vspace{0.5cm}
\noindent\textbf{Kata Kunci:} Captive Portal, Hybrid CRUD, Android Kotlin, AES-256 GCM, Code Coverage, Croot.js.

\chapter*{ABSTRACT}
\addcontentsline{toc}{chapter}{ABSTRACT}

Campus WiFi networks commonly rely on web-based captive portals that require users to repeatedly enter their credentials whenever sessions expire or devices roam across access points. This Project 2 develops, completes, and verifies the \textbf{Coneckin} ecosystem, consisting of a native Android application built with Kotlin and Jetpack Compose, a Node.js (Express 5) and MongoDB (\texttt{coneckin\_db}) REST API service, and a Croot.js-based landing page hosted on GitHub Pages (\texttt{coneckin.github.io}).

Core enhancements complete the Hybrid CRUD architecture by adding account editing (\textit{Ubah Akun}), duplicate validation, backup export/import, and local access hardening (PBKDF2WithHmacSHA256 PIN with brute-force lockout, forgot-PIN recovery, session-scoped verification, \texttt{BIOMETRIC\_STRONG}, and R8 minification) backed by local AES-256 GCM encryption (\texttt{AndroidKeyStore}), alongside full administrative CRUD endpoints (\texttt{/portals}, \texttt{/config}, \texttt{/reports}) protected by constant-time SHA-256 token verification (\texttt{timingSafeEqual}) and public read CORS support. Multi-layered automated testing achieves 90 Android JVM unit tests with 97.02\% line coverage, 11 Android instrumented tests validating \texttt{AndroidKeyStore} operations on an emulator, and 39 Express API tests reaching 96.53\% line coverage (140 automated tests in total). All test suites are enforced inside GitHub Actions CI/CD pipelines requiring at least 80\% line coverage prior to automated APK ($\approx 2.25$~MB) and AAB releases, and have been verified end-to-end across Alwaysdata production hosting and GitHub Pages.

\vspace{0.5cm}
\noindent\textbf{Keywords:} Captive Portal, Hybrid CRUD, Android Kotlin, AES-256 GCM, Code Coverage, Croot.js.
